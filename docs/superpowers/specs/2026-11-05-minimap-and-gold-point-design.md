# Дополнение: самообновляющаяся золотая точка крепости

Дополняет [основную спецификацию](2026-11-05-stronghold-finder-mod-design.md). Состояние: **реализовано в версии 1.1.0**.

## Что решил пользователь

- Точка крепости должна **сама менять координаты**: при каждом новом броске или другом изменении данных мод пересчитывает среднее (`avgX`, `avgZ`) и двигает точку.
- Через эту точку крепость показывается **на миникарте** Xaero's Minimap.
- Точку **можно удалить**, это не проблема: при следующем броске она появится снова.
- Цвет золотой.

Это заменяет прежний черновик с неудаляемым элементом нашего слоя и вариантами A–D для миникарты.

## Подход: обычный вейпоинт Xaero, которым управляет мод

Мод создаёт в Xaero's Minimap настоящий вейпоинт и обновляет его координаты. Так точка появляется на миникарте, на карте мира и в 3D-мире тем способом, каким Xaero показывает все свои вейпоинты, и не нужен второй набор классов для рисования на миникарте.

Из классов `xaerominimap-fabric-26.3-26.6.2` (проверено по jar, лицензия All Rights Reserved, в наш jar не входит):

- `xaero.common.minimap.waypoints.Waypoint(int x, int y, int z, String name, String symbol, WaypointColor color)` с методами `setX`, `setY`, `setZ`, `setName`: вейпоинт можно двигать на месте;
- `WaypointColor.GOLD`: золотой цвет уже есть в палитре Xaero;
- набор `xaero.hud.minimap.waypoint.set.WaypointSet` с методами `add`, `remove`, `getWaypoints`;
- путь к набору: `MinimapSession.getWorldManager()` → `MinimapWorldManager.getCurrentWorld()` → `MinimapWorld.getCurrentWaypointSet()`;
- сессия: `MinimapSession` берётся из `BuiltInHudModules.MINIMAP`.

Не проверено и входит в первую задачу плана: как точно получить текущую сессию из `BuiltInHudModules.MINIMAP`, нужно ли вызывать сохранение после `add`, как ведёт себя вейпоинт при смене мира и измерения.

### Как точка живёт

1. Любое изменение данных (бросок, удаление, включение или выключение броска, включение или выключение пересечения, отмена, очистка) приводит к пересчёту `Solution`. Это уже происходит в `ThrowStore`.
2. После пересчёта мод вызывает `GoldPoint.sync(solution)`:
   - **есть среднее и вейпоинт найден:** меняет `x` и `z` (и название с погрешностью);
   - **есть среднее, вейпоинта нет** (первый раз или пользователь его удалил): создаёт новый;
   - **среднего нет** (меньше двух рабочих лучей): убирает вейпоинт, если он есть.
3. Вейпоинт ищется в текущем наборе по метке: имя начинается с `Stronghold`, символ `S`, цвет `GOLD`. Ссылка на объект не хранится: пользователь мог его удалить или переименовать, и устаревшая ссылка вернула бы вейпоинт, которого уже нет.
4. Если пользователь переименовал точку, мод её больше не найдёт и создаст новую при следующем изменении. Это допустимо: правило «удалил, и она появится снова» уже принято.

### Параметры точки

| Параметр | Значение |
|---|---|
| Имя | `Stronghold ±N` на английском, `Крепость ±N` на русском, где N это погрешность в блоках. Язык берётся из настроек игры |
| Символ | `S` |
| Цвет | `WaypointColor.GOLD` |
| X, Z | округлённые `avgX`, `avgZ` |
| Y | `64`. Высота крепости неизвестна, а Y нужен Xaero (см. «Принятые решения») |

Только основной мир: в Нетере и Краю точка не создаётся и не двигается, потому что координаты там другие. Вейпоинт живёт в наборе обычного мира, который выбирает сама Xaero.

### Что становится с нашим слоем на World Map

Наш слой на World Map остаётся как есть: лучи, пересечения, круг погрешности, броски, средняя точка. Так World Map без миникарты работает прежним образом.

Чтобы не было двух меток в одном месте, наш жёлтый ромб средней точки не рисуется, когда вейпоинт существует и миникарта работает. Золотой вейпоинт Xaero тогда показывает точку на всех картах.

## Миникарта как зависимость

- Миникарта **необязательна**: в `fabric.mod.json` она попадает в `suggests`, а код вейпоинта грузится только при `FabricLoader.isModLoaded("xaerominimap")`. Иначе возникнет `NoClassDefFoundError`.
- Для компиляции миникарта подключается так же, как World Map: `compileOnly` и `localRuntime` из `maven.modrinth:xaeros-minimap:fabric-26.3-26.6.2` без транзитивных зависимостей.
- Модуль `GoldPoint` отделён в собственный пакет `dev.strongholdfinder.minimap` и вызывается только после проверки загрузки.
- Миникарта `26.6.2` требует World Map `>=1.47`? Не проверено. Версии в `fabric.mod.json` проверить при первом запуске.

## Ошибки

Любое исключение из кода миникарты ловится, пишется в лог один раз, и точка отключается до конца сессии. Клавиши, расчёт, экран и слой World Map продолжают работать. Предупреждение показывается на экране `J` рядом с предупреждением о слое карты.

## Тесты

- **Юнит (`core`):** выбор действия по состоянию: `GoldPointAction.of(solution, exists)` возвращает `MOVE`, `CREATE`, `REMOVE` или `NONE`. Проверяются все четыре случая, включая «среднего нет и точки нет» (`NONE`).
- **Юнит:** имя точки для обоих языков и округление координат, в том числе отрицательных.
- **В игре, с миникартой:**
  1. бросок создаёт один золотой вейпоинт с ожидаемыми `x`, `z`;
  2. второй бросок двигает **ту же** точку, а не создаёт вторую;
  3. удаление вейпоинта из набора, затем новый бросок создаёт его заново;
  4. удаление всех бросков убирает вейпоинт;
  5. в Нетере точка не создаётся;
  6. снимки миникарты и карты мира.
- **В игре, без миникарты** (текущий профиль): запуск без ошибок, слой World Map работает.

## Риски

- Xaero не публикует API. Классы вейпоинтов могут измениться при обновлении миникарты. Защита: изоляция в одном пакете, перехват исключений, тест в игре.
- Если `add` не вызывает сохранение, вейпоинт может не пережить перезапуск игры. Это не страшно: при следующем изменении данных он создаётся снова. Для остальных случаев точка заново создаётся при заходе в мир (мод пересчитывает данные при `JOIN`).
- Высота `Y=64` делает точку неточной по вертикали в 3D. Допустимо: нужна только точка на карте.

## Принятые решения

Пользователь поручил выбрать вариант на моё усмотрение. Выбрано:

1. **Y точки равен `64`.** Высота крепости неизвестна, а скачущий Y игрока делал бы точку нестабильной в 3D. Цена ошибки: точка по вертикали неточна, на картах это не видно.
2. **Наш жёлтый ромб скрывается, пока вейпоинт существует и миникарта работает.** Так в одном месте одна метка. Если миникарта не установлена или отключилась после ошибки, ромб рисуется как прежде. Цена ошибки: у игрока без миникарты ничего не меняется.
3. **Миникарта необязательна** и на Modrinth указывается как `Optional`. Без неё мод работает как раньше.

## Вне объёма

Лучи и круг погрешности на миникарте, кнопка скрытия точки на нашем экране (скрыть вейпоинт можно средствами Xaero), синхронизация точки с другими модами карт, неудаляемая метка нашего слоя.
